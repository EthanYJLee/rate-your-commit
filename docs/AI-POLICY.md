# AI 사용 정책

RateYourCommit의 8개 핵심 분석 기능 중 **6개는 규칙/통계**로만 처리되고, **AI(LLM)가 쓰이는 곳은 2곳뿐**이며 그마저도 최종 점수 계산에는 반영되지 않는 참고 기능입니다. 이 문서는 각 기능이 어떤 방식으로 동작하는지, AI가 어디에 쓰이고 어디에 안 쓰이는지를 정리합니다.

## 핵심 원칙

> **보상·등급에 직접 영향을 주는 계산에는 AI를 쓰지 않는다.**

이유: 보상은 "왜 이 점수를 받았는가"에 언제든 답할 수 있어야 합니다. AI(특히 딥러닝 모델)로 점수를 계산하면 설명 불가능한 블랙박스가 되어 이의제기에 대응할 수 없습니다. 그래서 `packages/scoring`은 순수 함수만으로 구성되고, 어떤 형태의 AI 호출도 금지됩니다 (강제 사항은 `docs/ARCHITECTURE.md` §4, `CONTRIBUTING.md` 참고).

## 기능별 방식

| # | 기능 | 방식 | AI 사용 | 실행 위치 |
|---|---|---|---|---|
| 1 | 작성자 이름 자동 매칭 | 규칙 기반 (이메일 완전일치, 문자열 유사도) | ❌ | 로컬 |
| 2 | 커밋-티켓 번호 매칭 / 이상치 제외 | 정규식 + 임계값 | ❌ | 로컬 |
| 3 | 코드 품질 측정 | 기존 정적분석 도구(SonarQube 등) 연동 | ❌ | 로컬 |
| 4 | 개인 종합 스코어 산정 | 가중합 (통계) | ❌ | 로컬 |
| 5 | 리스크 알림 | 임계값 기반 | ❌ | 로컬 |
| 6 | 결함·마일스톤 추이 집계 | 단순 집계·시각화 | ❌ | 로컬 |
| 7 | 커밋 메시지 난이도 요약 (선택) | LLM 요약 | ✅ | 로컬 LLM 또는 API 중 택1 |
| 8 | 동료평가 코멘트 요약 (선택) | LLM 요약 | ✅ | API 권장 |

7, 8번 기능 모두 **최종 점수 계산식에 입력값으로 들어가지 않습니다.** 화면에는 "참고 지표"로만 노출됩니다.

## 로컬 vs API — 선택 기준

- **로컬(local)**: 사내 서버에서 실행, 데이터가 외부로 나가지 않음. 소스코드 외부 유출 금지 등 보안 정책이 있는 조직은 이 방식을 사용해야 합니다. `.env`의 `AI_ASSIST_PROVIDER=local` + `AI_ASSIST_LOCAL_ENDPOINT`로 설정합니다.
- **API**: 외부 업체(Anthropic 등) 서버에 데이터를 전송하고 결과를 받음. 구축·운영 부담이 적습니다. `AI_ASSIST_PROVIDER=anthropic` + `AI_ASSIST_API_KEY`로 설정합니다. 동료평가 코멘트처럼 민감한 개인정보를 다루는 경우, 반드시 **학습에 데이터를 재사용하지 않는다고 계약된 기업용 API**만 사용하세요.
- 둘 다 비워두면(`AI_ASSIST_PROVIDER=`) AI-assist 기능은 완전히 비활성화됩니다. 기본값입니다.

## 기여 규칙

`packages/ai-assist`에 기능을 추가하는 PR은 환영하지만, 그 결과가 `packages/scoring`의 입력으로 흘러 들어가는 구조는 받지 않습니다. 자세한 내용은 `CONTRIBUTING.md`를 참고하세요.
